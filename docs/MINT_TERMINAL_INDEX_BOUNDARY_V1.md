# Mint → Terminal → Optional Tokenization → Index Boundary v1

HAPI World operates under the Carbon Actual distinction between minting and tokenization.

```text
MINT != TOKENIZE
MINT -> TERMINAL
TOKENIZE -> INDEX
```

Every material feedback/PULSE or other in-scope object may receive a mint identity/provenance record. A minted object is routed to **TERMINAL** for intake, holding, sorting, reconciliation, and curation.

A minted object may stop at Terminal. Minting alone does not make it useful, recognized, valuable, tokenized, or eligible for Index membership.

A timeout, DNS failure, network failure, inaccessible page, or other unsuccessful retrieval can consume value and generate minted feedback. The feedback remains accountable at Terminal without automatically entering Index.

Only explicit tokenization after Terminal-stage curation/eligibility and applicable authority, rights and provenance checks creates an Index representation.

```text
VALUE / ACTION / FEEDBACK
        ↓
      MINT
        ↓
    TERMINAL
        ↓
 CURATION / ELIGIBILITY
        ↓
   TOKENIZATION
        ↓
      INDEX
```

The no-waste rule remains active regardless of Index promotion: consumed value is reconciled through Proof, settlement, reconciliation, or ASH as appropriate.
