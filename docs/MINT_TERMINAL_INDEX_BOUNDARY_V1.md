# Mint → Terminal → Optional Tokenization → Index Boundary v1

HAPI World operates under the Carbon Actual constitutional distinction between minting and tokenization.

## Invariant

```text
MINT != TOKENIZE
MINT -> TERMINAL
TOKENIZE -> INDEX
```

Every material feedback/PULSE or other in-scope ecosystem object may receive a mint identity/provenance record. A minted object is routed to **TERMINAL** for intake, holding, sorting, reconciliation, and curation.

A minted object may stop at Terminal. Minting alone does not make it useful, recognized, valuable, tokenized, or eligible for Index membership.

A failed operation is validly represented this way. A timeout, DNS failure, network failure, inaccessible page, or other unsuccessful retrieval can consume value and generate minted feedback. The feedback remains accountable at Terminal without automatically entering Index.

Only explicit tokenization after Terminal-stage curation/eligibility and the applicable authority/rights/provenance checks creates an Index representation.

```text
VALUE / ACTION / FEEDBACK
        ↓
      MINT
        ↓
    TERMINAL
        ↓
 CURATION / ELIGIBILITY
        ↓
   TOKENIZATION
        ↓
      INDEX
```

The no-waste rule remains active regardless of Index promotion: value consumed by a failed/non-indexed operation is still accounted for through Proof, settlement, reconciliation, or ASH as appropriate.
