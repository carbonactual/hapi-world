# Mint → Terminal → Optional Tokenization → Index Boundary v1

HAPI World Nexus preserves the Carbon Actual distinction between minting and tokenization.

```text
MINT != TOKENIZE
MINT -> TERMINAL
TOKENIZE -> INDEX
```

Minting establishes accountable identity/provenance for in-scope PULSE, feedback, media, outcomes, capabilities, resources, discoveries, transactions and observations. The minted object is routed to **TERMINAL**.

Terminal is the universal intake, holding, sorting, reconciliation and curation boundary. A minted object may stop there. Minting never implies Index membership.

A timeout, DNS failure, network failure or inaccessible page can consume value and produce minted feedback. That feedback remains an accountable Terminal object even when it never becomes Index value.

Only explicit tokenization after Terminal-stage curation/eligibility and the required rights, authority, provenance and recognition checks promotes an object into Index.

```text
VALUE / ACTION / FEEDBACK
        ↓
      MINT
        ↓
    TERMINAL
        ↓
 CURATION / ELIGIBILITY
        ↓
   TOKENIZATION
        ↓
      INDEX
```

Failure/non-indexed outcomes remain subject to Proof, accounting, settlement, reconciliation and ASH/no-waste rules. Lack of tokenization does not erase consumed value or proof.
