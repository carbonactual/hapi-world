# HAPI World Repository Canon Law

**Status:** BINDING implementation law  
**Authority:** `CANON.md`

## Order of precedence

1. `CANON.md`
2. Canonical ontology and ratified acts
3. Typed schemas and API contracts
4. Architecture/RFCs
5. Implementation and tests
6. Experiments and historical material

## Non-negotiable rules

- Every implementation is attributable to a canonical entity and lifecycle.
- Identity (#) is distinct from authority, capability, activity and value.
- SealGrant governs consequential action; ABBA intelligence never manufactures authority.
- Events, evidence and current state remain distinct.
- Pulse is feedback, not automatically money, ownership or authority.
- Unknown state is preserved for investigation; unknown is not proof of malice.
- Ash preserves; Phoenix performs governed recovery/response.
- Product repositories consume common primitives and must not create competing constitutional meanings.

## AODS

Where a client surface uses AODS, its plate/habitat identity, token source, motion profile and accessibility boundary must be declared. The canonical 435 ordinal registry may contain unmapped plates and must not fabricate historical facts.

## Build conformance

The repository must retain deterministic validation, explicit contracts, auditable changes, and a blocking conformance job for canonical surfaces.
